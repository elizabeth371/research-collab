## 阶段 0：环境准备（约 10 分钟）

### 0.1 安装依赖
```bash
# 后端
cd backend
pip install -r requirements.txt
python -m pip install certifi        # arXiv 实时检索需要 CA 证书

# 前端
cd ../frontend
npm install
```

### 0.2 启动后端
```bash
cd backend
uvicorn main:app --host 0.0.0.0 --port 8000
```
- **验证**：`curl http://localhost:8000/api/health` 返回 `{"status":"ok",...}` → 见 TC-01
- 首次启动自动建表 + 写入演示用户/文档/文献种子语料

### 0.3 启动前端
```bash
cd frontend
npm run dev
```
- 浏览器打开 `http://localhost:5173` → 见 TC-03

### 0.4 冒烟（1 分钟）
- 页面三栏正常、无 Console 报错 → TC-03
- 后端状态提示不出现"后端服务未启动" → TC-23（反向验证）

## 常见问题排查

| 现象 | 排查方向 |
|------|----------|
| 页面提示"后端服务未启动" | 后端是否运行；`curl /api/health` 是否 ok；端口是否被占用 |
| 双标签页不同步 | 两个标签页是否同一文档；WebSocket 是否只有 1 条连接；重启后端重试 |
| Research 返回模拟结果 | 检查网络（arXiv 需联网）；改用含英文关键词的指令（如 `watermark detection`） |
| 水印检测显示异常 | 确认前端为最新代码（`npm run dev` 热更新后刷新页面） |
| 端口 8000/5173 被占用 | 修改 uvicorn 端口并同步 `frontend/vite.config.ts` 代理目标 |
| 溯源链显示"检测到篡改" | 按 TC-19 恢复数据，或确认是否真的有人改过数据库（预期行为） |
| 并发压测出现 500（UNIQUE constraint）或 verify invalid | 后端未加载修复后代码，重启 uvicorn 后重测（TC-26~28） |
