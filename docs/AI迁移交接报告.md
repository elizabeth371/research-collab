## 1. 项目速览

**定位**：面向科研诚信的多 Agent 协同写作平台，核心卖点是「AI 写作 → 学术审核 → 字符级水印溯源」的闭环。

| 层 | 技术 |
|---|---|
| 后端 | FastAPI + SQLAlchemy 2.0 async + SQLite（PostgreSQL 可选）+ LangGraph（每个 Agent 一张**单节点图**） |
| 前端 | React 18 + TypeScript + Vite + Tailwind + Tiptap/Yjs（实时协同）+ markdown-it |
| AI | OpenAI 兼容协议（默认 DeepSeek）、jieba 分词、Kirchenbauer 字符级绿名单水印 |

**布局**（单屏三栏 + 顶栏）：

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：品牌 · 文档切换/新建/上传/导出/稿件体检/设置 · 用户名   │
├───────────────┬──────────────────────────┬───────────────────┤
│ 左：Agent 写作流程 │ 中：协同编辑器（Yjs）      │ 右：水印/溯源/    │
│ 三 Tab：调研/写作/审核 │ 工具栏 + AI/人类着色 + 批注 │ 文献/聊天 四 Tab  │
└───────────────┴──────────────────────────┴───────────────────┘
```

## 2. 启动与验证

### 2.1 启动（Windows / Git Bash 实测可用）

```bash
# 后端（默认 8000；若被占用改用 8010，见 2.2）
cd backend
pip install -r requirements.txt
python -m uvicorn main:app --host 127.0.0.1 --port 8000

# 前端（5173，/api 与 /ws 代理到后端）
cd frontend
npm install
npm run dev -- --host 127.0.0.1
```

打开 **http://localhost:5173**（无痕或 Ctrl+F5 强刷避免缓存）。

### 2.2 端口冲突（本机现实情况）

开发机上 `8000` 端口被另一个项目（`Shop API`）占用。前端代理目标已支持环境变量：

```bash
cd backend  && python -m uvicorn main:app --host 127.0.0.1 --port 8010
cd frontend && VITE_API_TARGET=http://127.0.0.1:8010 npm run dev -- --host 127.0.0.1
```

`frontend/vite.config.ts` 中 `VITE_API_TARGET` 缺省为 `http://localhost:8000`。

### 2.3 环境变量（`backend/.env`，参照根目录 `.env.example`）

| 变量 | 说明 |
|---|---|
| `LLM_API_KEY` | DeepSeek/兼容服务 Key；**不配置则自动降级规则引擎**（可离线演示） |
| `LLM_BASE_URL` | 默认 `https://api.deepseek.com/v1` |
| `LLM_MODEL` | 默认 `deepseek-chat` |
| `WATERMARK_SECRET_KEY` | 可选；未配置时自动生成到 `.secrets/`（换机器会导致历史水印失效） |
| `DATABASE_URL` | 默认 PostgreSQL；不可用时回退 `SQLITE_PATH=./research_colab.db` |

### 2.4 必跑的质量门

```bash
cd backend && python -m pytest tests/ -q      # 当前：163 passed
cd frontend && npx tsc -b && npm run build    # 当前：0 错误
```

## 5. 不可破坏的业务规则

1. **严格串行**：每次 `/agents/invoke` 只跑一个 Agent（后端单节点图）；任何 Agent 不得自动触发下一步，下一步必须由用户点击。
2. **状态机唯一权威**：`frontend/src/lib/agentFlow.ts` 的流转表是唯一真源；所有推进必须经 `flowTransition`（`AgentPanel.go` / `goIfCurrent`）。
3. **审核/检测对象 = 文档实际内容**（读取编辑器状态，不是面板缓存文本）。
4. **写作默认不加水印**（保证流畅）；「带水印版本」是独立按钮触发的可选路径，徽章以服务端 `watermarked` 标记为准。
5. **润色会破坏水印**：任何「先注水印再润色」的顺序都是错的；体检固定为「润色 → 鉴定」。
6. **数据库访问必须参数绑定**；凭据只从环境变量读取。
7. **单进程部署**：会话与锁在内存中，`--workers N` 会破坏轮询与溯源链串行化。

## 6. 当前状态与已知问题（如实）

| 项 | 状态 |
|---|---|
| 纯 LLM 写作 | 流畅、约 2000 字、自动分段；**不含水印**，对正文检测会判「人类创作」 |
| 带水印写作 | z≈4.3–6.5 可检出；正文有少量重复虚词/缺字；耗时 2-5 分钟 |
| 检测口径 | 正常行文用全量 token；高重复文本（唯一 bigram <35%）自适应去重防误报 |
| 文献检索 | arXiv 在线优先；中文走领域词英译 + jieba 分词本地降级；结果自动入本地库（URL 去重） |
| 审稿 | 规则红黄牌 + LLM 语义意见（warning/info，不产生红牌） |
| 鉴权 | **无**（演示级）；公网部署前必须加 |
| 数据库 | `backend/research_colab.db` 曾被 git 跟踪（含演示数据与每文档密钥）；公开前应 untrack + 清理历史 |
| 网络 | 开发机到 github.com 偶发阻断，推送需重试 |
| 安全扫描提示 | `watermark_attack.py` 67/91/102 行使用固定种子随机数，属对抗实验的可复现性设计，非缺陷 |
| 前端构建 | 有 chunk >500kB 的警告，不影响运行 |

## 7. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面打不开 / 一直转圈 | 后端未启动或端口不对 | 检查 8000/8010 监听；确认 `VITE_API_TARGET` 与后端端口一致 |
| 所有接口 404 | 后端被其他项目占用端口 | 用 8010 启动后端并设置 `VITE_API_TARGET` |
| 搜索 0 条 | 中文查询且 arXiv 无结果、本地库也无匹配 | 换英文关键词或稍后重试；确认网络可达 arxiv.org |
| 写作报"执行超时" | 长稿 + LLM 慢 | 前端超时已放宽到 4-5 分钟；可重试 |
| 水印检测判"人类创作" | 正文是纯 LLM 版（未注水印） | 先点「生成带水印版本」再写入/检测 |
| 上传后体检未弹出 | 上传失败（格式/大小） | 仅支持 `.md/.txt/.markdown`，≤2MB |
| 中文在 curl 里乱码/解析失败 | Git Bash 编码 | 用前端验证；或在 Python 中发请求 |
