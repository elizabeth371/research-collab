# 水印对抗鲁棒性实验报告：多粒度与锚点模式（步骤 12）

> 项目：智溯 · 多智能体科研协同编辑与版权溯源系统
> 日期：2026-09-02 ｜ 引擎：Kirchenbauer 绿名单（4 种模式对比，DeepSeek logprobs 重采样注入）

## 1. 实验目的

步骤 11 实验已确认字符级 bigram 水印的两个边界：

- **局部乱序是固有弱点**：字符级 bigram 依赖相邻字符的绿名单关系，窗口乱序后 z 跌至人类水平（样本 A z=2.01、样本 B z=2.65）；
- **机器翻译回译部分失效**：跨语言改写后仅临界检出。

本轮目标：在**不牺牲字符级方案强鲁棒面**（删除/改写/噪声几乎不衰减）的前提下，设计并实证对**顺序扰动鲁棒**的中文水印变体，并将四模式在统一基准上对比，为论文提供"模式自适应选择"的实验依据。

## 2. 算法设计（4 种模式）

所有模式共用 Kirchenbauer 框架：绿名单 γ=0.5，检测统计量

```
z = (green − γT) / √(Tγ(1−γ))
```

z>4.0 判定为 AI 生成（Kirchenbauer 原文标准）。差异在**绿名单如何与文本结构绑定**：

| 模式 | 绿名单绑定方式 | 对顺序扰动的性质 |
| --- | --- | --- |
| `char_bigram`（基线） | 种子 = 密钥⊕前一字符，字符级 bigram 绿名单 | 位置相关，乱序即破坏 |
| `word_bigram` | jieba 分词 → 密钥绑定哈希得到词 ID，词内连续字符共享绿名单 | 位置相关，词序被打乱即破坏 |
| `unigram_anchor` | 文档级锚点种子（仅密钥），全文共享一张**位置无关**绿名单掩码 | 严格不变（检测按唯一字符去重计数） |
| `dual_anchor` | 注入同时叠加字符 bigram + 锚点两通道偏置；检测取 `max(z_char, z_anchor)` | 任一通道存活即可检出 |

实现要点：

- **锚点通道**：`_anchor_seed()` 由 `SHA256(secret_key + b"|anchor|")` 派生，与位置、前文、文档内容完全无关；全文共享一张绿名单掩码，检测端按**唯一字符**计数（去重），因此对任意重排严格不变。
- **双通道注入**：`dual_anchor` 不做 0.5/0.5 权重分裂，而是**加法偏置**——某字符同时落在两通道绿名单时获得 2δ 偏移（"双绿"字符被强化）。实测验证：拆分式注入使锚点通道仅剩 z≈2.5（统计功效不足），加法式注入后两通道独立可检（z_char≈13.4 / z_anchor≈6.1）。
- **闭源 API 适配**：DeepSeek 不暴露 logits，通过 `generate_with_logprobs` 逐位置取 top-20 候选，本地按绿名单偏移后重采样，实现与 logits 注入等价的偏置。
- **兼容性**：`char_bigram` 引擎标识保持历史值 `kirchenbauer-v1`，其余模式为 `kirchenbauer-{mode}`，旧证据包不失效。

## 3. 实验设置

- **注入**：真实 DeepSeek `deepseek-chat`，temperature=1.5，逐位置 top-20 logprobs 重采样，delta=4.0，γ=0.5。
- **样本**：20 个独立主题 × 4 模式 = 80 段注入文本（每段约 460–600 字符位置）。每样本只请求一次候选，四模式复用同一候选集，保证模式间可比。
- **攻击矩阵**（12 项，全部确定性、固定 seed）：`no_attack` 基线、随机删除 10/20/30/40% 字符、截断末尾 20%、中文同义替换、插入噪声字符、局部窗口乱序（窗口 2/4/6）、机器翻译回译 zh→en→zh（真实 DeepSeek 调用）。
- **人类基线**：10 段人工手写中文文本（每段约 80–100 字），度量四模式误报率。
- **持久化与续跑**：candidates/texts/rows 三级 JSON 断点续跑，中间进程中断不丢数据（本次实验曾中断一次，续跑自动补齐）。

## 5. 分析

1. **双通道方案完全解决乱序弱点**：`dual_anchor` 在窗口乱序 w2/w4/w6 下检出率全部 1.0（z≈7.32），而字符级基线跌至 0.95/0.45/0.10（z=5.93/3.92/2.90）。锚点通道与位置无关，乱序不损失任何统计量（anchor z 在三档乱序下严格等于 7.358±1.479 基线值，与理论设计完全一致）。
2. **几乎无质量代价**：`dual_anchor` 基线 z=15.93（字符级 17.29），且内容删改类攻击全线最稳——delete_40 后仍 1.0 检出（z=7.69），其余模式在 delete_40 出现 0.95 的零星回落。加法式双绿偏置没有带来可测的文本质量损失（字符保留率无异常）。
3. **word_bigram 是诚实的负面结果**：词级单元在重排下破坏比字符级更彻底（reorder_w6 检出率 0.0，z=1.59），翻译回译后 z 转负（-0.19）。原因：词 ID 绑定使破坏是"整词级"的，且 jieba 分词在回译后的文本上不稳定，词边界漂移导致评分错位。该模式不建议作为默认，但保留其作为"词级注入"的对照基线进入论文。
4. **翻译回译是四模式共同的开放弱点**：最高为 `char_bigram`/`dual_anchor` 的 0.3 检出（z=3.51），锚点通道在翻译后完全失效（z=-0.56，词表更换）。跨语言改写仍是本方案的理论边界。
5. **人类误报为零**：10 段人工手写文本在四模式下误报率全部 0.0，z 均值 −0.50~0.58 且远低于阈值 4——说明阈值收紧空间充足，可支撑更低 z>3 的无误报部署（供产品侧权衡）。
6. **锚点基线的 z 天然偏低**（7.36 vs 字符 17.29）：因检测按唯一字符去重，有效计数 T 减小，统计功效低于 bigram 通道。合成候选单元测试曾低估其功效（z≈2.5），真实 DeepSeek 数据上锚点 z 达 7.36，证实为合成数据（logprob 平铺）的伪象而非实现缺陷。

## 6. 结论与建议

- **默认模式建议切换为 `dual_anchor`**：对乱序鲁棒 + 内容攻击无损失 + 人类误报为 0，综合最优。
- **威胁模型为"段落重排/洗稿"的场景**：锚点通道严格不变，`unigram_anchor` 是理论最优选择（代价是基线统计量略低）。
- **论文写作建议**：以"4 模式 × 攻击矩阵 + 人类误报率"呈现，论证**按威胁模型自适应选择水印模式**的价值；word_bigram 负面结果如实报告，作为模式设计的消融对照。

## 7. 后续工作

1. **自适应 δ（低熵位置降权）**：对候选分布接近均匀的低熵位置降低注入强度，压缩质量代价（当前 delta 固定 4.0）。
2. **multi-bit 载荷水印**：在锚点/词级通道中编码文档 ID 与作者 ID（专利方向，可由"是否生成"升级为"谁生成"）。
3. **语义级/翻译鲁棒通道**：段落级统计签名或跨语言语义锚点，攻克 translate_roundtrip 这一共同弱点。
4. **产出**：论文实验章节草稿、专利交底书（系统组合 + 模式自适应）。
