## 七、发现并修复的问题

### 问题 1（功能 bug）：文档全文水印检测结果字段未映射

- **现象**：点击"检测当前文档全文并留痕"，面板恒显示"人类创作"、置信度 0%（NaN）、绿名单命中为空。
- **根因**：`api.ts` 的 `detectDocumentWatermark` 直接把后端 snake_case 响应（`is_ai_generated`/`confidence`/`watermark_chars`）断言为 camelCase 类型，未像 `detectWatermark` 那样做映射，导致组件读到的字段全是 `undefined`。
- **影响**：AI 水印文档无法在界面正确展示检测结果（留痕记录与溯源链不受影响）。
- **修复**：`frontend/src/lib/api.ts` 增加与 `detectWatermark` 相同的响应映射。
- **复测**：AI 水印文档显示"AI 生成（含水印）/ 置信度 100% / 61 字符"；人类文档显示"人类创作 / 424 字符"。✅

### 问题 2（数据不一致）：新建文档后顶栏时间显示异常

- **现象**：新建文档后，顶栏"最近更新"显示 Invalid Date。
- **根因**：`createDocument` 返回值按 camelCase 使用（`doc.updatedAt`），后端实际返回 `updated_at`。
- **修复**：`api.ts` 增加 `mapDocument()` 映射器，统一 `createDocument`/`listDocuments`/`getDocument` 的 snake_case → camelCase 转换。
- **复测**：新建文档显示正常时间。✅

### 问题 3（检索相关性）：英文指令关键词抽取被泛词挤占

- **现象**：指令 "retrieve recent papers about watermark detection for large language models" 检索到的是"论文检索/3D 模型检索"类无关论文。
- **根因**：`_extract_keywords` 停用词表只有中文，英文指令的前 3 个关键词全是 `retrieve/recent/papers` 等泛词。
- **修复**：`backend/services/agent_orchestrator.py` 扩充约 60 个英文研究动作/泛指停用词。
- **复测**：同一指令返回的全部为水印检测领域论文（Ensemble Watermarks、Watermarking Makes Language Models Radioactive、VOW、BiMarker、Signature filtering）。✅

### 问题 4（高严重度，D1）：并发写入同一文档触发 500 且溯源链断裂

- **来源**：`docs/AI测试验收报告_20260820.md` 缺陷 D1（高严重度）。
- **现象**：同一文档并发写入（多 Agent 写作 / 水印检测留痕 / 正文保存重叠）时，多个请求并发读取同一链尾 `prev_hash`，在同一秒（SQLite `CURRENT_TIMESTAMP` 秒级精度）内算出相同 `current_hash`，违反 `op_logs.current_hash` 的 UNIQUE 约束返回 500；部分日志写入失败导致哈希链断裂、verify 不通过。
- **根因**："读链尾 → 计算哈希 → 插入日志"非原子，无并发控制。
- **修复（采用验收报告方向 2：事务 + 串行化，零 DB 迁移）**：
  - `backend/services/oplog_chain.py` 新增按文档粒度的 `asyncio.Lock` 池（`oplog_append_lock(doc_id)`，惰性创建、线程安全）。
  - `backend/api/documents.py::update_document` 与 `backend/api/watermark.py::detect_document_watermark` 中"读链尾 → 追加日志 → 提交"过程整体包裹在 `async with oplog_append_lock(doc_id):` 内：同一文档串行、不同文档并行，哈希链线性约束不变，无需修改表结构或迁移现有数据。
- **复测证据**：
  1. **TDD 复现**：回归单测 `test_concurrent_writes_no_500_and_chain_valid` 在修复前代码上如实复现 IntegrityError，修复后通过。
  2. **全量回归**：`30 passed, 3 warnings in 3.16s`。
  3. **实时压测**：20 并发混合 PATCH + 全文水印检测 → 异常 0、4xx/5xx 为空、溯源链日志恰好 20 条（零丢失）、verify `{"valid": true, "checked": 20}`，`LIVE_CONCURRENCY_RESULT: PASS`。
  4. **存量数据**：演示文档 verify `valid: true`，链完整。
- **验收报告其余项**：第 5 节 UUID 连字符/无连字符存储差异经核对为验收方口径差异（数据库层以无连字符 hex 存储，API 层经 Pydantic 统一序列化为带连字符 UUID，属正常分层序列化），非缺陷；第 6 节演示数据清理为可选操作，未在本次范围内执行。

## 八、遗留限制与风险（非缺陷，属设计取舍）

1. **服务端纯转发，不持久化 Yjs 状态**：刷新后从数据库明文快照恢复，非 CRDT 增量。
2. **Agent 不调用真实 LLM**：Research 检索真实文献（arXiv/本地库），Writer 输出模板草稿，Supervisor 为规则引擎。
3. **水印为字符级 tokenizer 演示**：算法为论文级忠实实现，但未接入真实模型 logits/分词器（预留接入点）。
4. **无用户认证**：演示用户写死在种子数据，AUTH 消息预留未启用。
5. **arXiv 检索需联网**：无网络时自动降级本地文献库（演示链路始终可用）。
