# 智溯 · 多智能体科研协同编辑与版权溯源系统
## 软件使用说明书

> 面向科研诚信的多 Agent 实时协同与版权溯源系统
> （Multi-Agent Collaboration & AIGC Provenance System）

---

## 一、软件概述

### 1.1 软件名称

智溯 · 多智能体科研协同编辑与版权溯源系统（简称"智溯"）。

### 1.2 主要功能

| 编号 | 功能模块 | 说明 |
|------|----------|------|
| 1 | 实时协同编辑 | 基于 Yjs CRDT 的多端实时编辑，多光标互见，AI/人类作者内容着色区分 |
| 2 | 多智能体科研辅助 | Research（文献检索）、Writer（论文起草）、Supervisor（学术规范审查）三类 Agent 协同工作 |
| 3 | AIGC 水印检测 | 基于 Kirchenbauer 绿名单算法的 AI 生成内容检测，检测动作留痕可追溯 |
| 4 | 版权溯源链 | 操作日志 SHA-256 哈希链，任一历史操作被篡改即整链失效 |
| 5 | 文献检索与引用 | 关键词检索内置文献库，一键生成 GB/T 7714 引文并插入文档 |
| 6 | 文档导出 | 导出含溯源元数据的 Markdown 文件（标题/正文/溯源校验状态/参考文献） |

### 1.3 运行环境

- 服务端：Python 3.10+、FastAPI、SQLAlchemy 2.0（数据库自动回退 SQLite，无需额外安装）
- 客户端：Node.js 18+、现代浏览器（Chrome / Edge 最新版）
- 操作系统：Windows / macOS / Linux

## 二、安装与启动

### 2.1 启动后端服务

在项目 `backend` 目录执行：

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

首次启动自动完成：创建数据库表、写入演示用户与演示文档、写入 8 条文献种子语料。
数据库默认使用 `backend/research_colab.db`（SQLite）；若安装了 PostgreSQL 且
`DATABASE_URL` 可连接，则自动切换为 PostgreSQL。

### 2.2 启动前端

在项目 `frontend` 目录执行：

```bash
cd frontend
npm install
npm run dev
```

浏览器访问 `http://localhost:5173` 即进入系统主界面。

### 2.3 运行测试

```bash
cd backend
python -m pytest tests/ -q
```

全部用例通过即视为部署正确（当前共 29 个用例，覆盖哈希链校验、水印检测、学术规范审查、API 集成等）。
完整验收流程、测试样例与历史测试结论见同目录《测试工作流.md》《测试样例.md》《测试报告.md》。

## 三、操作说明

### 3.1 主界面布局

主界面为三栏布局：

- **顶栏**：系统标识、文档切换下拉框、"新建文档"按钮、"导出 Markdown"按钮、当前用户标识。
- **左侧栏（Agent 面板）**：文献检索 Agent、论文写作 Agent、导师审稿 Agent 的触发按钮与消息流。
- **中间栏**：协同编辑器主区域。
- **右侧栏（功能面板）**：三个标签页——"水印检测"、"溯源链"、"文献检索"。

### 3.2 实时协同编辑

1. 在顶栏下拉框选择或新建文档。
2. 在编辑器内直接输入内容，编辑器自动保存至服务端。
3. 打开两个浏览器标签页访问同一文档，任一标签页中的输入会实时出现在另一标签页；
   双方光标（多光标）互相可见。
4. 文档中 **AI Agent 生成的内容**以蓝色背景显示，**人类作者输入的内容**以白色背景显示，
   便于区分内容来源。

### 3.3 多智能体科研辅助（Agent）

在左侧 Agent 面板中：

1. **启动文献检索**：在输入框填写研究主题（如"AI 水印与版权溯源"），点击按钮。
   系统自动抽取英文关键词，优先通过 **arXiv API 实时检索**真实论文（标题、作者、年份、
   分类目录齐全），无网络或检索失败时自动回退到本地文献库，并在结果中标注
   `来源: arXiv 实时检索` 或 `来源: 本地文献库`。
2. **启动论文写作**：基于检索结果生成论文草稿段落，并写入编辑器正文
   （该段内容自动标记为 AI 作者，蓝色背景显示）。
3. **导师审稿**：对当前草稿执行学术规范静态检查，输出审稿意见：
   - ✅ 通过：草稿篇幅、引用编号、参考文献章节等符合要求；
   - ❌ 需修改：列出具体问题（如篇幅过短、引用编号不连续、缺少参考文献章节等）。

### 3.4 AIGC 水印检测

1. 切换右侧面板至"水印检测"。
2. 点击 **"检测当前文档全文并留痕"**：检测整篇文档是否包含 AI 水印，
   并自动生成一条检测历史记录（该动作同时写入溯源哈希链，可被审计）。
3. 也可在文本框中粘贴任意文本，点击"检测粘贴的文本"进行独立检测。
4. 检测结果以"人类创作 / AI 生成（含水印）"徽标与置信度进度条展示，
   下方列表展示历史检测记录（检测时间、模型、参数）。

算法说明：水印引擎为 **Kirchenbauer 绿名单水印（KGW）** 的论文级实现
（Kirchenbauer et al., "A Watermark for Large Language Models", ICML 2023，
见 `https://arxiv.org/abs/2301.10226`）：以哈希密钥与前序 token 的乘积
为随机种子生成词表置换，取前 γ 比例为绿名单；检测时统计绿名单命中率，
计算 z-score 与 p-value（`z > 4.0` 判定为 AI 生成），并对重复 bigram 去重，
置信度取 `1 - p-value`。实现参考了开源项目 lm-watermarking（Apache-2.0）
与 MarkLLM（EMNLP 2024），详见第五节"开源代码与许可"。

### 3.5 版权溯源链

1. 切换右侧面板至"溯源链"。
2. 面板展示该文档全部操作日志（插入 / 替换 / AI 生成 / 水印检测），
   每条记录含哈希值摘要，按时间正序排列并连线。
3. 顶部徽标显示整条链的校验结果：**"✓ 链条完整 · 未被篡改"** 或 **"✗ 检测到篡改！"**，
   并显示已校验的记录条数。
4. 点击"刷新"按钮重新加载并重新校验。

### 3.6 文献检索与引用插入

1. 切换右侧面板至"文献检索"。
2. 输入关键词（如"CRDT"）并搜索，结果列表展示文献标题、作者、年份、来源。
3. 点击某条文献的 **"插入引用"** 按钮，系统生成 GB/T 7714 格式引文
   （如 `Jahns P.Yjs: A Framework for Near Real-Time Peer-to-Peer Shared Editing on Arbitrary Data Types[J]. arXiv:2102.12943, 2021.`）
   并插入编辑器正文光标处。

### 3.7 文档导出

1. 点击顶栏 **"⬇️ 导出 Markdown"** 按钮。
2. 浏览器下载 `文档标题.md` 文件，内容包含：文档标题、导出时间、字数统计、
   溯源哈希链校验状态、正文（自动去除编辑格式标签）、水印检测记录、
   GB/T 7714 参考文献列表。
3. 该导出文件可直接作为论文底稿或版权证明材料使用。

## 四、常见问题

| 问题 | 处理方式 |
|------|----------|
| 页面提示"后端服务未启动" | 确认后端已在 8000 端口运行，`curl http://localhost:8000/api/health` 返回 ok |
| 编辑器内容刷新后丢失 | 内容已保存在服务端数据库，刷新页面后从数据库恢复；多端实时同步依赖 WebSocket 连接 |
| 水印检测返回"人类创作" | 当前文档由人工输入时属正常；AI 生成内容（蓝色段落）才带水印信号 |
| 溯源链校验显示失败 | 表示历史日志被修改，系统已成功识别篡改行为（预期行为） |
| 端口占用 | 修改 uvicorn 端口与 `frontend/vite.config.ts` 中的代理目标保持一致 |
