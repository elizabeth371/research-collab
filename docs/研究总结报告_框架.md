## 第一章 项目背景与研究意义
- 政策导向：GB 45438-2025 +《人工智能生成合成内容标识办法》（2025.9.1 施行）→ AIGC 显式/隐式标识法定化
- 现实痛点：生师比 17.14:1 反馈滞后；跨时空协同冲突；AI 内容溯源难、贡献边界模糊
- 研究意义：理论（群体智能垂直应用、人机交互实证）、应用（学术诚信工具）、社会（AI 治理合规）

## 第二章 国内外研究现状
- 多智能体：MetaGPT 角色化协同；PaperDebugger 编辑器内嵌 Agent；三元组织理论
- 实时协同：CRDTs/Yjs、y-websocket；AI 流式生成与 CRDT 原子操作的融合矛盾
- 文本水印：Kirchenbauer 绿名单；静态嵌入范式局限（重写/翻译/乱序破坏）；MorphMark 等自适应方案
- 核心不足归纳（对应申报书四大瓶颈）：角色化缺失、技术栈隔离、静态水印失效、三大维度未整合

## 第三章 系统总体设计
- 设计目标：一体化整合"多 Agent 专业化协同 + 实时协同编辑 + 动态水印溯源"
- 总体架构（分层：用户/协同编辑/多智能体服务/核心引擎/基础数据）
- 技术选型与理由：React 18 + Tiptap + Yjs ｜ FastAPI + SQLAlchemy(async) ｜ LangGraph + DeepSeek-V3 ｜ SQLite/PG 双库自动回退
- 数据模型：用户/文档/协作者/操作日志(哈希链)/水印记录/文献/批注/权限/版本/聊天 共 10 类核心表

## 第四章 关键技术实现
### 4.1 多智能体协同（调研/写稿/导师审稿）
- LangGraph 编排、SOP 流程、LLM 路径与纯规则引擎双模式
- 写稿润色（学术措辞表 + LLM 语义润色）、审稿红牌/黄牌分级与段落定位、一键润色该段
### 4.2 实时协同编辑
- Yjs CRDT + WebSocket 纯转发架构（服务端不持有状态，客户端收敛）
- 连接复用与 awareness 防回环、AI 蓝色标记作者着色、段落批注与漂移检测
### 4.3 AIGC 水印溯源（核心）
- Kirchenbauer 绿名单算法：`seed = hash(key, prev_token)`，z 统计量判定（阈值 4.0）
- 闭源 LLM（DeepSeek）无 logits 场景：logprobs 重采样 + 温度 softmax 注入（实测校准 temp=1.5、δ=4）
- 每文档独立密钥/参数（γ/δ 可调、可重建、变更留痕）
- SHA-256 哈希链溯源：每条操作日志哈希递推，逐条校验
- 对抗鲁棒性：6 类确定性攻击 + 真实机器翻译回译（实验结论见 4.4）
- 版权证据包：PDF/Markdown/JSON + package_hash 完整性校验
### 4.4 对抗鲁棒性实验（论文级数据）
- 攻击算子：随机删除 10%/30%、截断 20%、同义替换（16 组近义词表）、插入噪声、局部乱序（窗口 4）、zh→en→zh 真实回译
- 结论表（引用实验报告）：整体 14 项攻击检出 11 项（78.6%）；排除局部乱序 11/12=91.7%；如实标注乱序攻击失效边界
### 4.5 辅助能力
- 文献检索与 BibTeX 引用、文档导出（Markdown + 溯源元数据）、版本回溯（自动快照/恢复留痕）、权限管理（协作模式/水印策略/导出策略/协作者）、协作聊天（房间广播 + 持久化）

## 第五章 系统测试与验证
- 测试体系：pytest 144 项（单元/API/集成/端到端）+ 8 组 Playwright 浏览器实测（共 100+ 项检查）+ Docker 部署验证
- 关键结论：
  - 水印正样本检出 z≈8.9/置信度 100%，负样本不误判 z≈2.6
  - 哈希链篡改检测：改任意一条日志校验必失败
  - 版本恢复/权限 deny 导出拦截/聊天双向实时收发均验证通过
  - DB 终检：测试环境仅保留 2 个正式文档，无数据污染
- 测试文档索引：`docs/测试报告.md`、`docs/全方位测试验收报告_20260820.md`
